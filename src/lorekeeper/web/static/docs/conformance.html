Conformance

Two suites of JSON cases define what a client or server must do. They are plain data, so a port in any language can run them.

The suites

FolderWhat it testsNeeds the EPUB
conformance/*.jsonGating: positions in the example indexes and the exact view every client must produce.No
conformance/locators/*.jsonLocators: an edition, an index, a locator, and the expected seq and anchors.Yes, the Gutenberg EPUB for most cases

A client conforms if its view equals the expected view for every gating case (JSON equality, array order significant) and, for each locator form it supports, every locator case of that form. A server conforms if its responses match schema/api.schema.json, its views pass the gating cases, and it passes the locator cases for each form it accepts.

Gating case shape

{
  "description": "Holmes reveals his trade; the 'profession is a mystery' facet moves to history.",
  "series": "../examples/sherlock-holmes/series.json",
  "indexes": ["../examples/sherlock-holmes/study-in-scarlet.json"],
  "order": null,
  "finished": null,
  "position": { "book": "study-in-scarlet", "anchor": "ch2.para28" },
  "expect": { "lorekeeper": "0.1", "kind": "view", "position": { ... }, "coverage": { ... },
              "entities": [ ... ], "relations": [ ... ], "relationHistory": [ ... ],
              "events": [ ... ], "recap": null, "chapters": [ ... ] }
}

The inputs are the index files, the optional series manifest, a reading order (null for the default), a list of finished books (null for the default of every book before the current one) and the position. expect is the whole view, in the shape of schema/view.schema.json. There are fourteen cases, including a position before the first anchor, replacement across books, a book whose index is missing, an unfinished earlier book, and profiles inherited from an earlier book.

Locator case shape

{
  "description": "Word 240 of the chapter I document.",
  "edition": "corpus/pg244/pg244.epub",
  "index": "examples/sherlock-holmes/study-in-scarlet.json",
  "locator": { "spine": 4, "word": 240 },
  "expect": { "seq": 33, "exact": true, "finished": "ch1.para02", "inclusive": "ch1.para03" }
}

Map the locator onto the edition, check that seq and exact match, then resolve the index's anchors against that edition and check the anchor for each mode. A case whose edition file is missing is skipped by the Python runner, so a green run without the corpus does not cover locators. The README lists the download commands for the Gutenberg and Standard Ebooks files.

The suite has no error cases yet. Test the error rules of section 3.8 yourself: a malformed locator, members of two forms, and a missing or non-linear document must all fail, never guess.

Running the reference

uv run lorekeeper conformance            # run every case, prints ok / FAIL / skip per file
uv run lorekeeper conformance --update   # regenerate expected output after an intended change
uv run pytest                            # includes the same cases plus independent spoiler assertions
node tests/js/run_conformance.mjs        # the JavaScript gating port against the gating cases

Expected outputs are generated by the Python reference, so review the diff after --update. The spoiler properties that must never regress are also asserted by hand in tests/test_gating.py, independent of the generated files.

Validating an index

Index documents conform if they pass every check in section 6.4.

uv run lorekeeper validate my-book.lore.json
uv run lorekeeper validate my-book.lore.json --epub my-book.epub   # also checks anchors and quoted text
uv run lorekeeper validate book1.json book2.json --series series.json
