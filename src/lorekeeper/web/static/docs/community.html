Community indexes

Someone may already have built an index for your book. The app can check, let you try it in the real Reader without spoiling yourself, and add it to your library with one click. You can also share the ones you build.

This page is the app side. The file formats and the commands behind it are on Share an index, and section 8.7 of the specification is the authority.

Turn it on

Looking a book up tells the registry that you have it, so the app asks first. The first time you open a book's build page, a card where the ready-made index would be says what is sent and offers Turn on and Not now. Nothing is requested until you turn it on.

You can change your mind under Settings, in the Community indexes card. It has the same switch and the address of the registry. The default is https://nightspine.github.io/lorekeeper-registry. Any registry built with lorekeeper registry build works. Changing the address clears what the app has kept from the old one.

Find an index

Open a book's build page. With the feature on, a Ready-made block sits above the build options. It shows the best match as a sentence, such as "Whole book", then who shared it and, when it was audited, how many claims held up. If there is more than one, See all opens a sheet that lists them with the same facts in the same place on every row, sorted by best match or by newest.

A match means the shared index was made for exactly the text of your copy. Other editions of the same book are not offered yet. A book whose file is not on this server yet, such as a Book Orbit book you have not prepared, has nothing to look up, so the block is absent. So are the block for an unreachable registry and the one for a book nobody has shared. Series sets are not offered yet either.

What the facts mean

There are no star ratings. Each fact says who vouches for it, and the app never merges them into one score.

FactWhat it says
Whole book or PartialWhether the index covers the whole story.
Fit"Matches your copy exactly" in the list. After you open a preview, "N of N anchors found in your copy", counted by your own server.
CheckedAn audit reads "48 of 50 claims held up", and when some claims could not be judged from the passage cited, it says how many. Under it: checked by its builder, by the registry, by a reader, or by you. With no audit, a passing anchor and quote check reads "Anchors and quoting checked". Otherwise "Not checked yet".
Early namesOne line when a check found names shown before the book uses them. It gives a count and never the names. The listing carries its builder's count. Your server repeats the check on your own copy when you preview.
How it was madeThe model, or "Hand-written", and "edited by hand" when a person changed it. Also the licence, the version and the date.

The builder's numbers are the builder's word. A registry that holds no books cannot check them. That is why the app shows who checked, and why it checks again itself where it can.

Results are ordered by a fixed rule: whole books before partial ones, then those with no early names, then those with an audit (a higher lower bound on the share of claims that held up first), then newer ones.

Preview

Preview downloads the index, checks it and opens it in the Reader. Nothing is added to your library yet. A strip above the position panel says whose index it is and has Add to library and Back.

The checks run on your server before you see anything. The bytes must match the digest the registry published. The file must pass the schema and the validator, name your copy among its editions, and resolve its anchors against your EPUB. A file that fails the first ones is refused with the reason. Problems found only against your copy are counted and shown, not hidden.

The preview starts at the end of chapter 3, or at your Book Orbit position if that is further along. It is the real spoiler gate: nothing beyond the position is shown, and moving past it asks first, as it does for a synced position. Editing and merging are not available in a preview.

Check it yourself samples claims from the index and asks a model whether the book supports them. It appears only when a cloud provider key is saved, because a small local model judges too cautiously to give a fair number. It sends passages of the book to that provider, as a build does. The result is yours: it is kept on your server and sent nowhere else.

Add it to your library

Add to library (or Use this index on the build page) files the previewed index as a version of the book and opens the Reader on it. The message that confirms it has Undo. The index shows in the Library and in the book's versions as "Community, shared by" the publisher.

  • It becomes the book's default only if the book has no other version. It never replaces an index you built or edited, and when two are equally complete yours wins.
  • A community index is read-only here. Edit mode, merges and name tidying are refused for it with a clear message.
  • When a newer version of an index you use is shared, the build page says so and offers Update. The old file is kept. If it was the default, the new one takes its place.
  • Removing an installed index deletes the file and its record. The default falls back the way it does when you delete any version.

Share an index you built

On a book's Versions and runs page, each version built here has Share with the community. A finished run also offers it in the Runs monitor. The dialog runs your index through the same checks a registry would and lists what it found. Each item is marked pass, warning, fail or to do, in words and not only by colour.

  • It must validate, and the book's EPUB must be on this server.
  • A partial index is listed as partial.
  • The licence must be CC0-1.0 or CC-BY-4.0. If it is not, the dialog offers the two choices.
  • Early names are counted and shown as a warning. They do not block sharing.
  • The audit is optional and needs a cloud key. It checks 50 claims against the text and shows its estimated cost first.

Sharing is then two steps. Save the bundle downloads a file. Open the submission form opens an issue form in the registry's repository; drag the file into it. The submission is filed under your GitHub name, and a workflow runs the registry's checks and adds the listing. A book in a series cannot be shared from the app yet.

What is sent

WhenWhat leaves your server
You open a book's page, feature onOne request to the registry for the book's text fingerprint (a SHA-256 of its words). The answer is kept for 10 minutes. The request carries no account, key or book text. The registry host can see your IP address, as any web host can.
You preview or addOne request for the index file.
You run an auditPassages of the book go to your chosen cloud provider. Not to the registry.
You shareNothing, until you drag the saved file into the form yourself. The bundle holds the index and its check results, never the book. Edition labels and file hashes are removed from it.
Feature offNothing at all.

Your browser never talks to the registry. Only your server does.

How an index from outside is handled

Everything a registry returns is treated as input from a stranger. Requests time out after 10 seconds and stop reading at 6 MB. Redirects to another origin are not followed. A file link must point to the registry's own address and its index folder. JSON is parsed with limits on size and nesting. The downloaded bytes must match the published digest, and a mismatch is refused. The index then passes the schema and the validator before it is stored. The app shows its text as plain text and never as markup.

Turning it off

Switch it off in Settings. The app stops asking the registry at once. Indexes you already added stay in your library. To remove one, use its version list. The files live under community/ in the data folder, as described in Self-hosting.
