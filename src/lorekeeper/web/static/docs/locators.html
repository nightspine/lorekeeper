Locators

A reading system rarely knows a paragraph. It knows an EPUB CFI, a KOReader XPointer or a word offset. A locator says which, and the rules here turn it into one paragraph of the reader's own edition.

The five forms

A locator is a JSON object with exactly the members of one form. Over HTTP the members become query parameters of the same names.

FormProduced byPrecisionExample
blockClients that already hold the text modelExact{"block": 123}
cfiEPUB readers: Readium, Apple Books, KoboExact{"cfi": "epubcfi(/6/22!/4/108/1:0)"}
xpointerCREngine, so KOReaderExact{"xpointer": "/body/DocFragment[11]/body/div[3]/p[7]/text().0"}
spine and wordReaders that count wordsExact{"spine": 10, "word": 240}
spine and progressReaders that only know a fraction of the documentApproximate{"spine": 10, "progress": 0.42}

How a locator maps to a paragraph

The result is the seq of the block the locator points into, in the reader's own edition.

  • CFI. The spine step counts every item of the package spine, including non-linear ones, so the document is the spine item at step n divided by 2. The path after the ! walks element children of the document: an even step picks the element at that 1-based even index, an odd step a text node. The :n offset is a character offset. If the last [id] assertion names a different element than the steps reach, the asserted element wins, because an id survives edits that renumber children.
  • XPointer. DocFragment[n] is the 1-based index among all spine items, linear or not. The inner path uses element names with 1-based indices among same-named siblings, and text().n is a character offset.
  • Spine and word. spine counts only linear documents from 0. word counts normalized words in that document's blocks, from 0.
  • Spine and progress. The block whose cumulative word range contains the fraction, rounding down.
  • Which block. A CFI or XPointer lands on an element or text node. The block is the innermost block element containing the first text at or after that point.

Fallbacks and errors

Every rule errs towards the paragraph before, so a wrong guess can only reveal less.

SituationResult
Target lies between two blocks, or before the first block of its documentThe nearest preceding block, never the next.
Target is before the first block of the editionNone, which is seq -1.
Word offset past the end of a documentThe document's last block, marked approximate.
Character offset past the end of its textThe same block.
Document found, but the inner path does not resolveThe block before that document's first block, marked approximate.
Malformed locator, members of more than one form, or a document that does not exist or is not linear where the form needs itAn error. Clients must not guess.

A server reports an approximate result as "exact": false in the locator object of its response.

From a block to a position

The block is not yet the position. The mode decides how it becomes an anchor. In finished mode, the default, the block the reader is on is not finished, so the position is the last anchor at or before the previous block. In inclusive mode the block counts, so the position is the last anchor at or before it. Use finished for views and inclusive for a name the reader is looking at.

Worked example

Document 10 holds blocks 200 to 230, so its first block is seq 200. The locator {"spine": 10, "word": 240} falls in the word range of block 207, so the result is 207. In finished mode the position is the last anchor at or before seq 206. In inclusive mode it is the last anchor at or before seq 207. If block 207 carries an anchor, a name lookup there sees what that block reveals and the view does not.

With the repository's example, the CFI epubcfi(/6/10!/4/2/14/1:12) points into chapter I of the Gutenberg edition. It maps to seq 36 and is exact. The finished position is ch1.para05 and the inclusive one is ch1.para06.

Where this is specified and tested

The rules are section 3.8 of the specification. The reference code is src/lorekeeper/locators.py and the JavaScript port is in lorekeeper-client.js. Twenty-two cases in conformance/locators/ cover every form, and the conformance page says how to run them.
