The index format in brief

An index is one JSON file per book. This page is the short version of sections 4 and 5 of the specification.

Top-level fields

FieldMeaning
lorekeeper, kindFormat version (0.1) and document kind: index or series.
idA registry-unique slug for this index.
workTitle, authors, language and identifiers (Gutenberg, Open Library, Wikidata, ISBNs) that let a server find the index for a book.
seriesOptional. The series id and this book's key in it.
editionsThe text hash and file hash of each edition the index was built from or checked against. One is marked builtFrom.
coverageWhether the index is complete and the last anchor it covers (through). Partial indexes are valid.
provenanceTimestamps, license, generator and review records.
anchorsThe ordered list of paragraph fingerprints that everything else points at.
entities, relations, events, recapsThe content, all gated.

An example

Trimmed from examples/sherlock-holmes/study-in-scarlet.json in the repository. Hashes and a few items are shortened.

{
  "lorekeeper": "0.1",
  "kind": "index",
  "id": "sherlock-holmes.study-in-scarlet",
  "work": { "title": "A Study in Scarlet", "authors": ["Arthur Conan Doyle"], "language": "en",
            "ids": { "gutenberg": "244" } },
  "series": { "id": "sherlock-holmes", "book": "study-in-scarlet" },
  "editions": [{ "textHash": "3ba1a631...d4ff5", "fileHash": "d65612d1...b7e7", "builtFrom": true }],
  "coverage": { "complete": false, "through": "ch2.para51" },
  "provenance": { "created": "2026-10-21T00:00:00Z", "license": "CC0-1.0" },
  "anchors": [
    { "id": "ch1.para14", "fp": "6f0214b011388a35", "seq": 44 },
    { "id": "ch2.para28", "fp": "...", "seq": 131 }
  ],
  "entities": [{
    "id": "holmes", "type": "person", "from": "ch1.para14",
    "names": [
      { "value": "Sherlock Holmes", "kind": "primary", "from": "ch1.para14" },
      { "value": "Holmes", "kind": "alias", "from": "ch1.para27" }
    ],
    "facets": [
      { "id": "sis.holmes.1", "from": "ch1.para14", "basis": "stated", "evidence": ["ch1.para12", "ch1.para14"],
        "text": "A man Stamford knows from the hospital's chemical laboratory, who is looking for someone to split the cost of a set of rooms." },
      { "id": "sis.holmes.14", "from": "ch2.para28", "basis": "stated", "evidence": ["ch2.para28"],
        "replaces": ["sis.holmes.8"],
        "text": "Works as a consulting detective, perhaps the only one in the world." }
    ]
  }],
  "relations": [{ "id": "sis.rel.murray-watson", "src": "murray", "dst": "watson", "from": "ch1.para02",
                  "label": "orderly who saved the life of", "basis": "stated", "evidence": ["ch1.para02"] }],
  "events": [{ "id": "sis.ev.maiwand", "from": "ch1.para02", "summary": "Watson is wounded at the battle of Maiwand.",
               "entities": ["watson", "murray", "maiwand"], "evidence": ["ch1.para02"] }],
  "recaps": [{ "id": "sis.recap.ch1", "from": "ch1.para69", "evidence": ["ch1.para35"],
               "text": "Invalided home from Afghanistan and short of money, Dr. Watson needs cheap lodgings..." }]
}

Anchors and from

An anchor is a paragraph, identified by fp, the SHA-256 of its first twelve normalized words. The order of the anchors array is reading order, and an anchor's position in the array is its ordinal. The optional seq is a hint for one edition only. Clients compare ordinals and never ids or seqs.

Every name, facet, relation, event and recap has a from anchor, the point at which it becomes visible. An anchor marks the end of its paragraph, so something revealed at ch1.para14 appears once the reader has finished that paragraph. Facets, relations, events and recaps also carry evidence, anchors at or before from whose text supports the claim, and facets and relations carry a basis: stated or inferred.

Entities, facets and profiles

An entity is a person, creature, place, group, object, concept or term. Its names each have their own from, so a nickname can stay hidden until the story uses it. A facet is one statement about what the entity is: role, looks, nature, allegiance, status. Plot goes to events. A facet with kind: "profile" is a self-contained "who this is now" description. The last visible profile is the one a reader app shows, and earlier ones become history.

Relations, events and recaps

  • Relations connect two entities with a label, such as "orderly who saved the life of". A relation is visible only when both endpoints are.
  • Events are things that happen, listing the entities involved.
  • Recaps are story-so-far text. A recap with scope: "chapter" belongs to one chapter, and the view lists every visible chapter recap in reading order.

replaces and history

A facet or relation may list ids in replaces. Once the replacing item is visible, the replaced ones move to history. They remain true statements about what the reader once knew, and an app can show them under "Earlier impressions". Replacement only points backwards, within the book or to an earlier book of the series, so an index can be generated forward without editing earlier files.

Series

A series manifest (kind: "series") lists the books, their reading orders (publication, chronological) and the default order. Entity ids are series-scoped. Each book's index lists only that book's names and facets, and the gating algorithm merges them across the books the reader has finished. An optional carried block is a fallback copy of an earlier book's entities, used only when that book's index is missing.

Editions and hashes

The textHash identifies an edition's text regardless of metadata, images or styling: the SHA-256 of every normalized word of every block, in order. The fileHash identifies one exact EPUB file. A server's lookup route matches on either, which is how a reader app that holds a different edition of the same book still finds an index, with anchors resolved by fingerprint alone.
