Protocol reference

The read-only HTTP API a Lorekeeper server offers to reader apps and plugins. It is section 8 of the specification, written out route by route.

The protocol is separate from the web app's own /api, which is private to the web interface and can change at any time. The routes here are all GET, return UTF-8 JSON, report errors as application/problem+json (RFC 9457) and send CORS headers so browser-based readers can call them. A running server also publishes them as OpenAPI at /api/docs, which is handy for trying requests. The examples use http://localhost:8765 and the bundled example index.

RoutePurposeCapability
GET /.well-known/lorekeeperWhat the server offers.always
GET /v0/lookupFind indexes for a book.lookup
GET /v0/indexes/{id}Fetch an index.index
GET /v0/series/{id}Fetch a series manifest.series
GET /v0/indexes/{id}/viewThe gated view at a position.view, view-cfi
GET /v0/indexes/{id}/entitiesWho is this name?entities

Discovery

GET/.well-known/lorekeeper

Always public, even when a token is required. No parameters.

curl http://localhost:8765/.well-known/lorekeeper

{"lorekeeper":"0.1","name":"Lorekeeper","api":"/v0",
 "capabilities":["lookup","index","series","view","view-cfi","entities"],
 "auth":{"type":"none"}}
MemberMeaning
lorekeeperThe protocol and format version.
nameA display name for the server. Set it with the LOREKEEPER_SERVER_NAME environment variable.
apiThe path prefix of the other routes.
capabilitiesRoutes and features on offer. view-cfi means cfi and xpointer locators are accepted, because this server holds editions.
auth.typenone or bearer.

Lookup

GET/v0/lookup

Finds indexes for a book. Give at least one parameter. When you give several, an index matches if any of them does, and its match reports the strongest.

NameTypeRequiredMeaning
fileHashstringone of theseSHA-256 of the EPUB file.
textHashstringText hash of the edition (specification 3.4).
isbnstringISBN-10 or ISBN-13. Hyphens are allowed.
gutenbergstringProject Gutenberg ebook number.
openlibrarystringOpen Library work id.
wikidatastringWikidata item id.

The response is {"results": [...]}, best match first. Within a quality, complete indexes come before partial ones.

Result memberMeaning
idUse this in the other routes. It is stable on one server.
titleThe work's title.
matchfile for the same file, text for the same text, identifier for an ISBN or catalogue id match, which may be another edition.
completeWhether the index covers the whole book.
digestsha256: and 64 hex digits. Equals the ETag of the fetch route.
hrefThe path of the index.
seriesOptional: {{id, book}}.
updatedOptional timestamp from the index's provenance.
curl "http://localhost:8765/v0/lookup?textHash=3ba1a6316fb65ab87f83bbbc65d66b82d0313be6a836e20770dc9571bd8d4ff5"
curl "http://localhost:8765/v0/lookup?gutenberg=244"
curl "http://localhost:8765/v0/lookup?isbn=978-0-14-043787-2"

Errors: 400 when no parameter is given, 401 without a required token.

Fetch an index

GET/v0/indexes/{id}

Returns the index document, which is the file as stored (index format). The path parameter id is the id from lookup. Cache it by ETag and gate locally.

curl -i -H 'If-None-Match: "sha256:1c87e7bc...fe74a51"' http://localhost:8765/v0/indexes/examples--sherlock-holmes--study-in-scarlet
HTTP/1.1 304 Not Modified

Errors: 401, 404 when there is no such index.

Fetch a series manifest

GET/v0/series/{id}

Returns the series manifest. Here id is the series id, for example sherlock-holmes, as in an index's series.id. It lists the books, the reading orders and the default order. Same caching as the index.

curl http://localhost:8765/v0/series/sherlock-holmes

{"lorekeeper":"0.1","kind":"series","id":"sherlock-holmes","title":"Sherlock Holmes",
 "books":[{"key":"study-in-scarlet","title":"A Study in Scarlet","ids":{"gutenberg":"244"}}, ...],
 "orders":{"publication":["study-in-scarlet","sign-of-four"]},"defaultOrder":"publication"}

Errors: 401, 404.

View

GET/v0/indexes/{id}/view

The spoiler-safe view of the index at a position, in the shape of schema/view.schema.json. Give exactly one position: an anchor, or one locator form with textHash or fileHash. Sending an anchor with a locator, or two locator forms, is an error. This route sends the reading position to the server.

NameTypeRequiredMeaning
anchorstringone positionAn anchor id of the index.
blockintegerone positionLocator: the block seq in the reader's edition.
cfistringone positionLocator: an EPUB CFI such as epubcfi(/6/22!/4/108/1:0).
xpointerstringone positionLocator: a CREngine XPointer. Must start with /.
spineintegerwith word or progressLocator: 0-based linear spine document.
wordintegerwith spineLocator: 0-based word in that document.
progressnumber 0..1with spineLocator: fraction of that document. Approximate.
textHashstringwith a locatorText hash of the reader's edition. Either this or fileHash.
fileHashstringwith a locatorSHA-256 of the reader's EPUB file.
inclusivetrue or falsenoWhether the current paragraph counts. See below for defaults.
orderstringnoA reading order key of the series. Default: the series default.
finishedcomma listnoBook keys the reader has finished. Default: every book before the current one.

inclusive defaults to false here, so the paragraph being read does not count. Only these combinations are valid: anchor, block, cfi, xpointer, spine with word, spine with progress.

The body is a view with entities, relations, relationHistory, events, recap and chapters. When a locator was used it also carries one more member:

{ ..., "locator": { "position": "ch1.para05", "seq": 36, "basis": "cfi", "exact": true } }
MemberMeaning
positionThe anchor id the view was gated at, or null for none.
seqThe block the locator mapped to. -1 for none.
basisThe form used: block, cfi, xpointer, word or progress.
exactFalse for progress and for a fallback; otherwise true.

The server resolves a locator only against an edition it holds: the one the index was built from, or another EPUB it stores, found by text hash or file hash.

Errors: 400 for a missing, repeated or malformed position, an unknown anchor or reading order, or a locator without a hash; 401; 404; 409 when the edition is not held; 501 if the server cannot map locators.

Entities

GET/v0/indexes/{id}/entities

Answers "I tapped this name; who is it?" without fetching the whole view. It returns what filtering the view for the same position would give.

NameTypeRequiredMeaning
namestringyesA visible name or alias, compared case-insensitively, or a surname that no other visible entity shares.
anchorstringone positionAn anchor id of the index.
blockintegerone positionLocator: the block seq in the reader's edition.
cfistringone positionLocator: an EPUB CFI such as epubcfi(/6/22!/4/108/1:0).
xpointerstringone positionLocator: a CREngine XPointer. Must start with /.
spineintegerwith word or progressLocator: 0-based linear spine document.
wordintegerwith spineLocator: 0-based word in that document.
progressnumber 0..1with spineLocator: fraction of that document. Approximate.
textHashstringwith a locatorText hash of the reader's edition. Either this or fileHash.
fileHashstringwith a locatorSHA-256 of the reader's EPUB file.
inclusivetrue or falsenoWhether the current paragraph counts. See below for defaults.
orderstringnoA reading order key of the series. Default: the series default.
finishedcomma listnoBook keys the reader has finished. Default: every book before the current one.

Here inclusive defaults to true, because the reader is looking at the name. Names that are not visible at the position never match.

curl -G "http://localhost:8765/v0/indexes/examples--sherlock-holmes--study-in-scarlet/entities" --data-urlencode "name=Holmes" \
  --data-urlencode "cfi=epubcfi(/6/10!/4/2/30/1:0)" --data-urlencode "textHash=3ba1a6316fb65ab87f83bbbc65d66b82d0313be6a836e20770dc9571bd8d4ff5"

{"position":"ch1.para14",
 "entities":[{"id":"holmes","type":"person","name":"Sherlock Holmes","aliases":[],"profile":null,
   "facets":[{"id":"sis.holmes.1","text":"A man Stamford knows from the hospital's chemical laboratory, ...","basis":"stated","book":"study-in-scarlet"}],
   "history":[],"relations":[],"events":[]}],
 "locator":{"position":"ch1.para14","seq":44,"basis":"cfi","exact":true}}

Each element of entities has the members of a view entity, plus relations and events listing the visible ones that involve it. The array is empty when nothing matches. Errors are those of the view route, plus 400 when name is missing.

Errors

Every error is a problem document with type, title, status and usually detail.

StatusSlugWhen
400bad-requestA parameter is missing, malformed or contradicts another.
401unauthorizedA bearer token is required and missing or wrong. The response carries WWW-Authenticate: Bearer realm="lorekeeper".
404not-foundNo such index or series, or an unknown path under /v0.
405method-not-allowedAnything but GET and OPTIONS.
409edition-not-heldThe server does not hold the reader's edition, so it cannot map a locator. Fall back to local gating.
501not-implementedThe server cannot map locators.
{ "type": "https://lorekeeper.dev/problems/not-found", "title": "No such index", "status": 404, "detail": "nope" }

CORS

All protocol responses, including errors and 401, send these headers, and a preflight OPTIONS to any protocol path is answered with 204 and no token check.

Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Authorization, If-None-Match
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Expose-Headers: ETag
Access-Control-Max-Age: 600

Because the origin is open, the bearer token is the only thing that stops another web page from reading an exposed server. Do not expose a server without one.

Authentication

By default there is none: a server on localhost needs no token. For a server on a network, set a token in one of three ways, listed from least to most careful:

LOREKEEPER_API_TOKEN=s3cret uv run lorekeeper web --host 0.0.0.0     # environment variable
uv run lorekeeper web --host 0.0.0.0 --api-token s3cret               # flag; visible in shell history
uv run lorekeeper web --host 0.0.0.0 --api-token-file ~/.lk-token     # first line of a file

The flag overrides the environment variable. With a token set, every protocol route except discovery needs the header, and auth.type in discovery turns to bearer. The comparison is constant-time.

curl -H "Authorization: Bearer s3cret" http://localhost:8765/v0/lookup?gutenberg=244

curl -i http://localhost:8765/v0/lookup?gutenberg=244          # without the header
HTTP/1.1 401 Unauthorized
www-authenticate: Bearer realm="lorekeeper"
{"type":"https://lorekeeper.dev/problems/unauthorized","title":"Unauthorized","status":401,
 "detail":"send Authorization: Bearer <token>"}

The token protects /v0 and the discovery document only. The web app itself, with its uploads, builds and settings, has no login. Read exposing the server before binding to a network address.

Caching

  • Index and series bodies carry ETag: "sha256:...", equal to the digest in lookup results, and Cache-Control: private, max-age=0, must-revalidate. Revalidate with If-None-Match. A weak tag, a comma-separated list and * are accepted. A match returns 304 with no body.
  • Views and entity answers have no ETag. They depend on the position, so cache them in your app if at all, and never past the reader's position.
  • Lookup results change when the library changes, so revalidate by digest rather than caching them for long.

The authoritative text is section 8 of the specification, and the authoritative schemas are in schema/api.schema.json.
